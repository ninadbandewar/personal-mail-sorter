Privacy Policy

Last updated: 12 November 2026

This Privacy Policy explains how Local Mail Sorter handles information when you use the desktop application. Local Mail Sorter is designed to run on the user's computer. It is not a hosted email service, and the application maintainer does not operate a central service that stores users' mailbox contents.

In brief: The application accesses a Gmail account only after the account holder authorises it. Email information, application settings, classification history and learning feedback are stored in the application's local data files. In the standard configuration, AI processing is sent to an Ollama service running locally on the user's computer. If the user configures a different model endpoint or service, relevant email content may be sent to that endpoint.

1. Information the application accesses

Depending on the features the user enables and the permissions granted, Local Mail Sorter may access or process:

  • Email message identifiers, sender and recipient details, subject lines, dates, message snippets and message bodies.
  • Gmail labels and message state, such as read or unread status.
  • Information needed to organise messages, including applying or removing labels, archiving, changing read status and other actions explicitly initiated or configured by the user.
  • User-created categories, sender rules, application settings, classification results, corrections and confirmed learning examples.
  • OAuth authorization tokens and related account connection information needed to maintain the Gmail connection.

The application does not need a user's Google password. Google handles sign-in and authorization through its OAuth process.

2. Google Gmail API and permissions

When a user connects Gmail, the application uses the Google Gmail API under the permissions shown on Google's OAuth consent screen. The application may request the Gmail modify permission to read messages and manage labels and message state. If a user invokes a feature requiring broader mailbox permissions, Google may display additional permissions on the consent screen.

Users should review the permissions displayed by Google before granting access. A user can revoke the application's access at any time through their Google Account security settings.

3. How information is used

Information accessed by the application is used to provide the features the user requests, including:

  • Classifying email into the user's configured categories.
  • Applying user-selected labels and mailbox actions.
  • Showing email details, classification explanations and review suggestions in the desktop interface.
  • Using user-confirmed classifications and corrections as examples to improve future classifications for that user's local application.
  • Maintaining account connections, application settings and local classification history.

User-confirmed classifications and corrections may be retained as learning examples in the local application database. An unconfirmed model prediction should not be treated as a user-confirmed correction.

4. Local storage and AI processing

The application stores its database, settings, classification history and OAuth token files in its local application folders. These files may contain email-related information and should be protected like the mailbox itself. Anyone with access to the computer account or those files may be able to access that information.

In the standard configuration, the application sends the text selected for classification to an Ollama model service running at a local address on the same computer. The application may send message subject, sender information, body text and relevant learning examples to that model service. Attachments are not necessarily processed; availability depends on the application's current features.

If the user changes the model endpoint, uses a network-hosted model service, or configures another external integration, the information sent to that service will be subject to that service's own privacy practices and configuration. The user is responsible for choosing and securing any non-local endpoint.

5. Sharing and sale of information

The application maintainer does not receive users' mailbox contents through a central Local Mail Sorter server, and does not sell email content or use it for advertising. Information is transmitted to Google as needed for Gmail authentication and API operations, and to the model endpoint or other service that the user configures.

This website is a simple information page. It does not provide an account portal or collect mailbox contents. The website host may process ordinary web request information under its own policies.

6. Data retention and deletion

Email-related records and learning examples may remain in the local application database until the user removes them or deletes the relevant local application data. Deleting local application data does not delete the original messages in Gmail. Gmail messages are changed or deleted only when the user invokes an application feature that performs that action.

To stop future Gmail access, revoke Local Mail Sorter's access in your Google Account. To remove locally stored application information, close the application and delete the relevant Local Mail Sorter data files after making any backup you need. Take care: deleting the database also removes local settings, history and learning examples.

7. Security

The application is intended for local use. Users are responsible for maintaining operating-system security, restricting access to their computer, protecting backups, and not sharing OAuth token files or database files. No method of electronic storage or transmission can be guaranteed to be completely secure.

8. Children's privacy

Local Mail Sorter is not designed specifically for children. A parent or guardian should supervise any use by a minor and should ensure that the account holder understands and authorises the Gmail permissions requested.

9. Changes to this policy

This policy may be updated when application features, integrations or data practices change. The “Last updated” date at the top indicates the date of the latest revision posted on this page.
